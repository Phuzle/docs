## `@phuzle/permit`

### `definePermissions(config)`

Takes your blueprint and returns a fluent builder. `config` should be declared with `as const` so
every role/resource/action name is inferred as a literal type.

### The role builder

Chained off `definePermissions(config)`:

<TypeTable
	type={{
		".role(name)": {
			type: "(name: keyof config.roles) => RoleBuilder",
			description: "Switches which role subsequent .can()/.cannot() calls apply to.",
		},
		".can(action, resource, when?)": {
			type: "(action, resource, when?: WhenFn) => RoleBuilder",
			description:
				'Grants an action on a resource for the current role. "*" matches any action/resource. An optional third argument makes it conditional (ABAC) — see the type signature below.',
		},
		".cannot(action, resource, when?)": {
			type: "(action, resource, when?: WhenFn) => RoleBuilder",
			description:
				"Explicitly denies — always overrides a matching .can(), regardless of specificity. See the Deny rules guide.",
		},
		".build(options?)": {
			type: "(options?: BuildOptions) => CompiledEngine",
			description: "Compiles the blueprint into an engine. options.audit registers a hook fired on every engine.check() denial.",
		},
	}}
/>

`WhenFn` is `(ctx: WhenCtx) => boolean`, where `ctx` is:

```ts
interface WhenCtx {
	user: { id: string; [k: string]: unknown };
	scopeContext: Record<string, string | undefined>;
	resource?: unknown; // whatever you passed as resourceAttrs — narrow with `as` at the call site
	action: string;
	resourceType: string;
}
```

## `@phuzle/permit/react`, `/vue`, `/svelte`

Each re-exports `hydrate`/`createLiveClient` from `/client` plus framework-native
`AccessProvider`, `usePermissions`, and `Can`. See
[Framework adapters](/permit/guides/framework-adapters) for the exact shape of each (Vue's
`usePermissions()` returns plain reactive getters; Svelte's returns a store).

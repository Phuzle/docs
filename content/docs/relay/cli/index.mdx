---
title: Command line
description: Send a notification from a shell, a cron job or CI with the relay command.
---

Install it from the same package as the SDK, or run it without installing:

```bash
npm i -g @phuzle/relay       # then: relay send …
npx @phuzle/relay send …     # one-off, e.g. in CI
```

The CLI encrypts on your machine, then sends. Sign in once, or use an API key.

## Sign in with `relay login`

```bash
relay login
```

It prints a short code (like `BCDF-GHJK`) and a link; press **Enter** to open it in your browser (nothing opens until you do, and you can open the link on another device). Sign in to the console, check the code matches, pick the organisation
and what this machine may do (send to all or some topics, receive events, create topics) and how long the key lasts, then approve. The
CLI picks the key up on its own; there is nothing to copy. Add `--no-browser` on a server or over SSH (or when there is no terminal) and open the link yourself, or
pre-fill the choices with `--org`, `--send all|<topic>,…`, `--receive …` and `--create-topics` (you still decide on the page).

The key is kept in `~/.relay/credentials.json` (readable only by you), per API URL, and shows up in **API keys** in the console marked
**CLI** with the machine's name. Only admins and owners can approve a login.

```bash
relay whoami     # the organisation and permissions of the stored login
relay logout     # revokes that key and forgets it
```

`RELAY_API_KEY`, when set, always wins over the stored login, which is what you want in CI. The SDK never reads the file: in code you
keep using the API key you give it. Keys made by `relay login` start with `rly_cli_`; keys from the console start with `rly_`.

## With an API key

```bash
export RELAY_API_KEY=rly_...
relay send --topic acme-alerts --title "Backup finished" --body "412 GB in 6 min"
```

On success it prints `sent <id> → 2 devices` and exits `0`. Any failure prints a one-line reason
and exits `1`, so it works in `set -e` scripts and CI steps.

## Save your defaults

```bash
relay configure                                  # asks for each value; Enter keeps the current one
relay configure --name shivam-cli --api-url https://relay.example.com
relay configure list                             # the API key is shown masked
relay configure unset api-key
```

`configure` keeps the API URL, API key and the consumer name for `relay listen` in `~/.relay/config.json` (readable only by you), so
you stop repeating flags. Order of precedence: a flag, then the environment variable (`RELAY_API_URL`, `RELAY_API_KEY`,
`RELAY_CONSUMER_NAME`), then this file, then a `relay login`, then the default. The SDK never reads the file.

## Help and version

`relay --help` lists the commands; `relay <command> --help` (or `-h`, or `relay help <command>`) shows one command's options and
examples. `relay --version` (or `-v`) prints the version. Errors say what went wrong, then what to do about it, for example which
setting a refused key needs.

## Topics and devices

```bash
relay topics                                   # topics this key can send to, and whether it can create more
relay topics create deploys --name "Deploys"   # needs "Can create topics" on the key
relay devices --topic acme-alerts              # the phones receiving a topic
```

Add `--json` to `topics` or `devices` for machine-readable output. A key limited to one topic lists just that topic. Only a key
that can send to all topics can be allowed to create topics.

## Receive webhooks on your laptop

```bash
relay key                                                 # a new consumer key (keep it secret)
relay listen --topic acme-github-api --forward http://localhost:3000/webhooks/github
```

`listen --out events.ndjson` appends every event to a file as one JSON line (the same object `--json` prints), so another process can
tail it, or pass a named pipe (`mkfifo`) to feed one directly. An event counts as handled only after it is written; if the write fails
it stays on Relay and comes back.

`listen` prints each event and, with `--forward`, POSTs it to your local server with the original headers: a
webhook tunnel with no public address. It says what it is doing (connecting, connected, reconnecting, stopped), with the time in
front of every status line, and Ctrl-C stops it cleanly, even while it is still retrying to connect. Options: `--name` (the
consumer's name shown in the console, default `cli`, or `RELAY_CONSUMER_NAME`; use something like `shivam-cli` to tell machines apart), `--key`
(otherwise `RELAY_CONSUMER_KEY`, otherwise a key kept in `~/.relay/consumers`), `--from last-acked|latest|<seq>`, `--json`, `--count N`.
An event is marked handled once it is printed or, with `--forward`, once your server answers below 500; otherwise it
comes back after 30 seconds.
See [Relay Streams](/relay/streams).

## Options

| Flag | |
|---|---|
| `--topic` | Full topic name, `<org>-<topic>` (required) |
| `--title` | Notification title (required) |
| `--body` | Message text |
| `--priority` | `min`, `low`, `default`, `high`, `urgent` |
| `--url` | An HTTPS link: tapping the notification opens the message and then the link in an in-app browser |
| `--icon` | A built-in icon name such as `rocket`, `flame`, `bug` (see the [message schema](/relay/api/message-schema)) |
| `--tag` | A short label; repeat for up to five |
| `--group` | Stacks related notifications together |
| `--ttl` | Seconds to keep trying to deliver |
| `--action` | A request button, `"Label=METHOD https://…"`; repeat for up to three in total with `--link` |
| `--link` | A button that opens a page, `"Label=https://…"` |

Environment: `RELAY_API_KEY` (required) and `RELAY_API_URL`. To use a local, staging or self-hosted Relay, set `RELAY_API_URL` or pass `--api-url https://your-relay.example` (the flag wins).

## Buttons

```bash
relay send --topic acme-alerts --title "Disk 91%" --priority high \
  --action "Acknowledge=POST https://ops.example.com/ack/db-1" \
  --action "Reboot!=POST https://ops.example.com/reboot/db-1"
```

A `!` after the label marks the button destructive, so the phone asks before it fires.

To add a button that just opens a page in the browser, use `--link`:

```bash
relay send --topic acme-alerts --title "Deploy finished" \
  --link "Dashboard=https://app.example.com/deploys/482" \
  --action "Roll back!=POST https://ops.example.com/rollback/482"
```

Buttons from `--action` and `--link` share the limit of three. See [Actions](/relay/app/actions).

## In CI and cron

```bash
# GitHub Actions step
- run: relay send --topic acme-ci --title "Deploy ${{ job.status }}" --priority high
  env:
    RELAY_API_KEY: ${{ secrets.RELAY_API_KEY }}
```

Keep the key in your CI's secret store. Prefer a key limited to the one topic it sends to.

To hold, repeat or escalate a message see [On-call](/relay/sdk/on-call): `--delay 10m` / `--at <time>`, `--repeat 5m:3`, `--escalate-topic <topic> --escalate-after 10m`.
